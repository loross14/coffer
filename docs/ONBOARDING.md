# Guided first run

New installations open the six-step setup. Existing installations with registered vaults keep their workspace. Setup is stored in `onboarding.json` beside the native registry and resumes after a restart; gathering permission is deliberately not retained as a checked box.

1. Browser account connection, using the existing PKCE handoff and Keychain credential.
2. A local agent connection. Codex and Claude Code terminal install through the existing native installer. A successful hook timestamp after this setup attempt is required; an installed configuration alone cannot advance. Claude Code also provisions Console reporting through the signed-in Mac account. Codex's local memory/reader is account-key-free; its separate project reporting is not provisioned here. Claude desktop is explicitly separate and cannot pass the terminal-hook check.
3. Discover existing Obsidian vault locations from its local registry, select folders, or Add all. Each failed registration remains visible and retryable. Files stay in place.
4. Select the World Knowledge destination and optionally describe its purpose.
5. Install the local model or continue without it.
6. Explicit permission to gather source context and create World Knowledge. Native creation reads source notes under both checkpoint and retrieval exclusions and publishes a source-backed navigation vault. There is no model-generated synthesis claim. With no eligible notes, a user-written purpose is required; an empty template cannot complete setup.

`Start Here.md` links per-vault source maps. Each map carries original-file links, headings, short attributed excerpts and SHA-256 fingerprints. A creation receipt binds the operation, source IDs, paths and generated bytes. Source files are never edited. The new vault receives a native checkpoint and is verified before the app opens. Retrying the same operation verifies the generated bytes and resumes registration/history; it does not adopt an unrelated or edited destination. Unsupported scope filters fail closed.

Limits: this is a point-in-time navigation map, not automatic ongoing synthesis. Individual source files over 512 KiB and hidden, symbolic-link or non-Markdown entries are omitted. A source exceeding 5,000 eligible notes or 100,000 visited entries stops with a scope-repair message. The UI discloses these bounds. Account signup uses the browser's existing account creation path within the same connection handoff. Claude desktop and Codex project-reporting provisioning remain separate integrations.

Verification uses disposable stores and source folders. Run `swift test --disable-sandbox` with `PLANISPHERE_GRAPHEINE_SOURCE` pointing to the pinned engine. Set `PLANISPHERE_ONBOARDING_SNAPSHOTS` to an output directory for all six steps in light/dark mode; these snapshots do not initiate sign-in or modify host agent settings.

## Downstream routing contract

`World-Knowledge.json` uses schema `planisphere.world-knowledge/1`. Each evidence entry contains a stable `originalID` derived from vault ID and exact relative path, explicit root and path, full original fingerprint, title, aliases/topics, observed modification time and read time, and unassessed-authority and snapshot-freshness qualifications. Canonical identity means the original file pointer; it never establishes authoritativeness. Per-vault coverage names applied exclusions, scope fingerprint, indexed and oversized counts, and bounds. Aliases, topics, tags and keywords support simple YAML scalars/lists only; complex YAML is left uninterpreted. The hooks owner can use these phrases to match a prompt's three topics and resolve original notes. This release does not change prompt delivery, reminder budgets, or shipped hook policy; that separate experiment requires personal validation and later approval.
